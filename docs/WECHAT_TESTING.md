# 微信公众号接入与测试方案

> 目标：在**不拥有麦当劳公众号开发权**的前提下，完整验证「发一句话 → 自动下单 → 返回支付链接」。

---

## 0. 先厘清一件事：这个公众号是谁的？

**是你自己的，不是麦当劳的。**

| 角色 | 归属 | 说明 |
|---|---|---|
| 前台（收消息、回消息） | **你的公众号** | 你 100% 掌控，用户关注的是你的号 |
| 后厨（菜单、算价、下单） | 麦当劳 MCP | 官方开放能力，通过 Token 调用 |

麦当劳开放的是**后厨能力**，不是前台。因此本项目不需要、也不可能获得麦当劳官方公众号的开发权限。

> ⚠️ **合规提醒**：公众号名称、头像、简介**不要使用麦当劳商标或易被误认为官方的表述**（如"麦当劳官方点单"）。活动规则明确禁止"暗示官方背书、误导公众"。建议用中性名称，例如「麦麦快捷点单助手」。

## 1. 四档测试路径（由易到难）

### 🥇 Tier 0 — 本地模拟器（**零外部依赖，今天就跑**）

| 项 | 值 |
|---|---|
| 需要什么 | 只装 Node ≥ 22.22.2（低于此版本 `node:sqlite` 不可用） |
| 需要公众号吗 | ❌ 完全不需要 |
| 需要公网吗 | ❌ 不需要 |
| 能验证什么 | 意图解析、门店/餐品匹配、会话状态机、二次确认、幂等、mock 下单全流程 |

```bash
npm run demo          # 终端里模拟一整段对话
npm run chat          # 有 Token 时走真实 MCP（不落真单）
```

**这是本项目的主要演示入口，也是给别人看的第一眼。** 评审者 clone 下来不用申请任何账号就能玩。

---

### 🥈 Tier 1 — 微信接口测试号（**推荐，真机收发**）

| 项 | 值 |
|---|---|
| 入口 | https://mp.weixin.qq.com/debug/cgi-bin/sandbox?t=sandbox/login |
| 需要注册主体吗 | ❌ 不需要，微信扫码即开 |
| 需要微信认证吗 | ❌ 不需要 |
| 接口能力 | **与认证服务号相同**（含客服消息、JS-SDK），仅微信支付/小店不可用 |
| 有效期 | **无限制**（早年的一年限制已取消） |
| 粉丝上限 | 100 人 |
| 接口频率 | 比正式服务号更严格 |

**步骤**

1. 打开测试号页面 → 微信扫码登录 → 记下 **AppID / AppSecret**
2. 填「接口配置信息」：
   - `URL`：你服务的**公网 HTTPS 地址**（见第 2 节内网穿透）
   - `Token`：任意 3–32 位字符串，例如 `mcdtest2026`（**必须与 `.env` 的 `WECHAT_TOKEN` 一致**）
3. 点提交 → 微信服务器发 GET 验签 → 本项目回 `echostr` 即通过
4. 扫页面上的二维码关注该测试号 → 直接在微信里发 `巨无霸 香梅北`

**这一步能验证被动回复 5 秒超时、客服消息异步推送这些真实链路，是 Tier 0 无法覆盖的。**

> 📌 **必须处理的两条官方行为**（developers.weixin.qq.com 一手来源）：
> 1. **微信 5 秒收不到响应会断连并重试 3 次**（同一消息最多投递 4 次）。来不及处理时**直接回复 `success` 或空串**可抑制重试，这是官方推荐做法；同时须按 **MsgId 去重**（事件按 FromUserName+CreateTime），对应 SPEC FR-24 / 任务 T37。
> 2. **客服消息有 48 小时窗口 + 条数限制**（超窗报 45015）。本项目的异步推送发生在用户消息后数秒内，不受影响，但做延迟类功能前必须知道这条。

> ⚠️ **资料置信度说明**：下表「与认证服务号相同」「无有效期限制」来自二手资料（开发者社区/代理商文章，非微信官方文档）；「粉丝上限 100」多源一致、置信度较高。**以测试号页面上的「体验接口权限表」实测为准**。

### 🥉 Tier 2 — 个人订阅号上线（长期自用）

| 项 | 值 |
|---|---|
| 主体 | 个人（身份证 + 手机号即可注册订阅号） |
| 能认证吗 | ❌ **个人主体无法微信认证** |
| 接收消息 / 被动回复 | ✅ 可用 |
| 客服消息接口 | ❌ **不可用** |
| 自定义菜单 | ❌ 不可用 |

**结论：核心链路完全可用**，只是"5 秒超时后异步推送"要降级。

降级策略（已写入 SPEC FR-21）：

```
用户在微信发消息
   ↓
服务 5 秒内被动回复「正在为你查询…」
   ↓
后台继续跑 MCP（耗时长）
   ↓
结果暂存 → 用户**下一次任意发言**时回补结果
```

## 2. 公网回调：微信必须访问得到你

微信服务器只会回调 **80/443 端口的 HTTPS 地址**，本机 `127.0.0.1` 不行。三种办法：

| 方案 | 适合 | 说明 |
|---|---|---|
| **内网穿透**（ngrok / cpolar / natapp） | 开发与测试号联调 | 一条命令把本地端口映射成公网 HTTPS，最快 |
| 云服务器（腾讯云轻量等） | 长期稳定 | 有固定公网 IP，可配正式域名 |
| 云函数 + API 网关 | 低成本长期 | 按调用计费，需注意冷启动 |

```bash
# 示例：把本地 8787 映射成公网 HTTPS
ngrok http 8787
# 拿到 https://xxxx.ngrok-free.app 后填进测试号的 URL，记得带路径 /wechat
```
