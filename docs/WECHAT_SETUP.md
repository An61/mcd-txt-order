# 公众号接入：分步实操手册

> 本文是**操作手册**。方案选型（测试号 / 订阅号 / 企业微信、为什么不需要麦当劳的开发权）见 [`WECHAT_TESTING.md`](WECHAT_TESTING.md)。
>
> 全程约 15 分钟。跟着做完，你就能在微信里发一句话下单。

---

## 第 0 步：先确认本地能跑

```bash
node --version            # 需 ≥ 22.22.2（订单幂等依赖内置 node:sqlite，22.6 会失败）
npm run doctor            # 环境体检：Token、门店、菜单是否就绪
npm run demo              # 离线演示，不花真钱
```

`npm run doctor` 全绿再往下走。它不通过时后面每一步都会失败，别跳。

---

## 第 1 步：配置 `.env`

```bash
cp .env.example .env
```

必填四项：

| 变量 | 从哪来 | 不填会怎样 |
|---|---|---|
| `MCD_MCP_TOKEN` | https://open.mcd.cn/mcp 手机号登录 → 控制台 → 激活 | 只能跑演示模式，无法真实下单 |
| `WECHAT_TOKEN` | 公众号后台「服务器配置」里**你自己填**的令牌 | 微信验签不通过，配置保存失败 |
| `WECHAT_APP_ID` | 测试号 / 公众号后台首页 | 不填则客服消息关闭，走「下次发言回补」降级 |
| `WECHAT_APP_SECRET` | 同上 | 同上 |

> ⚠️ `WECHAT_TOKEN` 是你自己编的字符串（3–32 位），**不是微信给的**。它要和你第 3 步在网页上填的**完全一致**，两边对不上就验签失败。

---

## 第 2 步：起服务，并暴露到公网

```bash
npm run serve             # 默认 8787
```

```bash
curl http://127.0.0.1:8787/healthz     # 应返回 ok
```

服务**只监听 `127.0.0.1`** —— 这是刻意的，开发机不该把回调端口暴露到局域网。公网访问交给内网穿透显式建立：

```bash
ngrok http 8787           # cpolar / natapp 同理
```

拿到 `https://xxxx.ngrok-free.app` 后，**第 3 步的 URL 要带路径 `/wechat`**：

```
https://xxxx.ngrok-free.app/wechat
```

> 微信只回调 **80/443 端口的 HTTPS**。`http://` 或带端口号的地址一律不行。

---

## 第 3 步：在公众号后台填服务器配置

以**接口测试号**（扫码即用、免认证）为例，入口：
https://mp.weixin.qq.com/debug/cgi-bin/sandbox?t=sandbox/login

| 字段 | 填什么 |
|---|---|
| URL | `https://xxxx.ngrok-free.app/wechat` |
| Token | 与 `.env` 的 `WECHAT_TOKEN` **逐字符一致** |
| EncodingAESKey | 随机生成即可（明文模式下不参与校验） |
| 消息加解密方式 | **明文模式**（对应 `WECHAT_ENCRYPT_MODE=plain`） |

点提交，微信会立刻发一个 GET 请求验签。本项目回显 `echostr` 即通过。

**失败时的第一反应**：99% 是 Token 两边不一致，或者 URL 忘了带 `/wechat`。

---

## 第 4 步：扫码关注，发第一句话

扫测试号页面的二维码关注它，然后在微信里发：

```
巨无霸 星河
```

预期收到一张预览卡片（门店、明细、优惠、应付金额），回复「确认」才会真正下单。

## 排错表

| 现象 | 原因 | 处理 |
|---|---|---|
| 服务器配置保存失败 | `WECHAT_TOKEN` 两边不一致 / URL 缺 `/wechat` | 核对这两个，其余都不用查 |
| 能收到消息但回复很慢 | MCP 链路超过微信 5 秒 | 这是设计内行为：先回「处理中」，结果用客服消息推回。要真正推送需配 `WECHAT_APP_ID/SECRET` |
| 同一条消息回了 4 次 | 微信 5 秒超时重试 3 次 | 已按 MsgId 去重；若仍出现说明去重窗口被打穿，检查是否多实例各自持有内存 |
| 客服消息报错 45015 | 超出 48 小时交互窗口 | 本项目推送在用户发言后数秒内，正常不会触发 |
| 回复「确认」却没下单 | 确认令牌 5 分钟过期，或已作废 | 重发点单指令拿一张新预览 |
| 一切正常但 `create-order` 报缺参 | `takeWayCode` 取不到 | 代码会直接中止而不是猜值，这是保护；检查 `calculate-price` 是否返回了 `takeWayList` |

## 上生产前必须改的三件事

1. **配 `CONFIRM_SECRET`**：确认令牌的 HMAC 密钥默认随机进程密钥，多实例部署时各实例互不认账，必须显式配置成同一个值。
2. **不要改 `ORDER_REQUIRE_CONFIRM`**：该开关仅在演示模式生效，真实 MCP 模式下代码级强制开启，改不动也不需要改。
3. **合规**：公众号名称、头像、简介**不得使用麦当劳商标或暗示官方背书**，例如「麦当劳官方点单」。建议用中性名称。

## 端口与端点速查

| 端点 | 方法 | 用途 |
|---|---|---|
| `/` | GET | 网页模拟器（单文件、断网可用，给别人看的第一眼） |
| `/api/chat` | POST | 模拟器用的 JSON 对话接口 |
| `/wechat` | GET | 服务器配置验签，回显 `echostr` |
| `/wechat` | POST | 消息接收（5 秒超时 → 后台继续 → 异步推送） |
| `/healthz` | GET | 健康检查 |
